## Project updates

**Accessible Housing** welcomed a new volunteer and got everyone access to run the project on their own computers. The team went through the accessibility fields in its spreadsheet with its community partner. It also reworked the database so each record is a single unit, the way MLS listings work, instead of a whole building, and removed features the new model no longer needs. The team is getting a demo ready for next Friday to get feedback from stakeholders.

The team needs developers and a designer to work on a logo and visual identity.

**LoMo** went through its front-end design and feature requirements page by page. The team merged its React front end and Django back end into one codebase, which puts it on good footing. The design is nearly done, all low fidelity for now, and the team is testing it against real use cases. A login issue in Django should be easy to fix, and once it is, work on the API can start. After that comes connecting the front end to the back end and fleshing out features.

LoMo is short on developers.

**Waterloo Region Votes** kept exploring a tabbed layout built around candidate pages, where voters can filter for the races that affect them. The team talked about weaving topics and resources through the whole site, and about where the project fits among other voting resources so it reaches interested voters. Some questions need answers before it goes further. Linking to candidate questionnaires is fine, but copying them needs permission. Not every candidate wants endorsements from advocacy groups shown, so the team needs a policy on that. The current site is still the ward-based version from 2022, and the team will keep working on how people find their way around it.

Waterloo Region Votes needs people to test the development site and may need help contacting sources about using their information.
